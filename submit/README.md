# Submission contents

The brief requires the deliverables to be **uncompressed** and named
`report.pdf` and `[filename].Java` or `[filename].cpp`. Two files:

| file | what it is |
|---|---|
| `../report/report.pdf` | the report, compiled from `report/report.typ` (rename to `report.pdf` when submitting) |
| `DBBench.java` | the whole benchmark program as a single compilable file |

## DBBench.java

Generated by `tools/make_single_file.py` from `benchmark/src/bench/*.java`. It is
the same code as the multi-file repository with only the mechanical changes a
single-file Java build requires: no package declaration, `public` dropped from the
top-level types (Java permits one public class per file), and the entry point
renamed `Main` -> `DBBench`. The generator verifies the result by compiling it.

Build and run:

```bash
# file backend -- no dependency at all
javac DBBench.java
java -cp . DBBench --backend file --mode scan --keyword the --data ./data

# SQL backends -- put exactly ONE JDBC driver on the classpath
javac -cp "lib/postgresql-42.7.4.jar" DBBench.java
java -cp ".:lib/postgresql-42.7.4.jar" DBBench --backend pg \
     --jdbc jdbc:postgresql://127.0.0.1:5432/bench --user bench --pass bench \
     --mode scan --keyword the

java -cp ".:lib/opengauss-jdbc-5.0.0.jar" DBBench --backend og \
     --jdbc jdbc:postgresql://127.0.0.1:5433/bench --user gaussdb --pass 'Bench@123' \
     --mode scan --keyword the
```

Run without arguments to print nothing useful; the flags are listed in the file
header. `--help` is not implemented, which is the one rough edge of this file.

## Why exactly one driver jar

`opengauss-jdbc` is a fork of pgjdbc and ships `org.postgresql.Driver` as well, so
two driver jars on one classpath shadow each other. The symptom is a confusing
`Protocol error. Session setup failed.` against PostgreSQL. The repository's
`benchmark/run.sh` selects the classpath per backend for this reason.

## The rest of the project

The scripts, SQL, data preparation and analysis are in the repository
(`scripts/`, `sql/`, `analysis/`, `data/`, `out/`), together with the raw
measurements the report is generated from. `out/raw.csv` holds 1,787 timed runs;
`report/gen_tables.py` regenerates every table in the report from that file.
